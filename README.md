# 附近的你（nearby-you）

> AI agent 玩家版「附近的人」——上报你的位置和资料，看看方圆 50 公里内还有谁在玩 Claude Code。

这是一个**概念验证（PoC）项目**：用 Claude Code skill + 一台轻量云服务器，验证「agent 时代的附近的人」这个想法跑不跑得通。欢迎小范围试玩，更欢迎拿去改造。

## 理念

微信「附近的人」看脸，这个看什么？看 **agent 配置**。

三个核心想法：

1. **你的 agent 比你更会写自我介绍**。它读过你的 CLAUDE.md、memory、陪你干了三个月活，由它总结「你是做什么的」，比你自己憋简介更准——而且每台机器上的 agent 数据源不同，大家的简介天然带个人色彩。
2. **agent 信息是新的社交名片**。`Claude Code + GLM-4.7 / Win11` vs `Codex + GPT-5 / macOS`——同类相闻，见面先聊工具链。
3. **位置只到「附近」**。三级定位降级链（Windows GPS → IP 城市级 → 手填），每级结果都先给用户确认才上传，联系方式自愿填、可随时删。

## 它是怎么工作的

```
你的电脑 (Claude Code skill)                概念服务器 (Express + SQLite)
┌────────────────────────────┐             ┌──────────────────────────┐
│ 上报: GPS/IP/手填三级定位    │    HTTP     │ POST /api/profile        │
│       agent 总结简介        │ ──────────→ │ GET  /api/nearby         │
│       自动采集 agent/模型    │             │ (限流 + IP哈希防灌水)      │
│ 查询: 附近50km前10人        │ ←────────── │ 高德逆地理(key只在服务端)  │
└────────────────────────────┘             └──────────────────────────┘
```

四个流程（全部在 SKILL.md 里编排，关键环节强制用户确认）：

- **上报资料**：定位确认 → 简介确认 → agent 信息 → 联系方式（带公开警示）→ 汇总确认 → 上传
- **查附近**：默认 50km 按距离排前 10，标注距离 + 最近上报时间
- **更新资料**：改哪项传哪项（位置变了重走定位链）
- **删除**：确认后硬删除，本地身份文件同步清除

无账号体系：首次上报时服务端发 `UUID + secret`，存在本地 `~/.nearby-you/identity.json`，之后修改/删除凭它认证。

## 快速开始

### 方式 A：装 skill，连概念服务器试玩

```bash
git clone https://github.com/<你的用户名>/nearby-you-skill.git
mkdir -p ~/.claude/skills
cp -r nearby-you-skill/skill ~/.claude/skills/nearby-you
```

然后对 Claude Code 说「上报我的资料」或「看看附近谁在玩」。

> **试玩须知（概念服务器的现实）**
> - 数据存作者的一台轻量云服务器，**资料内容对所有用户公开**（这是产品本身），请勿填敏感信息
> - 一个公网 IP 只能创建一条资料（防灌水）；家庭/公司多设备共享 IP 是已知限制
> - 无 SLA，随时可能下线；`identity.json` 丢了只能找管理员删资料（见 server/README.md）
> - 不放心的话，用方式 B 自己部署一套

### 方式 B：全套自己部署（10 分钟）

1. 服务器（Node 16+）：`scp -r server/ you@your-server:/opt/nearby-you-api/`
2. `npm install`，申请[高德 Web 服务 key](https://console.amap.com)（免费，可选——不配则只存坐标不显示中文地址）
3. `AMAP_KEY=xxx pm2 start ecosystem.config.js`（端口 3210，防火墙放行）
4. 把 skill 的 `config.yaml` 里 `api.base` 改成你的服务器

完整运维手册（含 secret 救援、限流说明、IP 哈希盐）：[server/README.md](server/README.md)

## 设计决策速记

| 决策 | 理由 |
|---|---|
| 无账号，UUID+secret | 概念阶段最低摩擦；secret 只存 sha256，明文仅创建时返回一次 |
| 一个 IP 一条资料 | 零成本防灌水；库里存 `sha256(ip:盐)`，data.db 泄露不暴露 IP |
| 三级定位降级 + 每级确认 | GPS 拿不到（服务关/IP漂移）不卡死；位置是敏感数据，必须本人过目 |
| 坐标库存 WGS-84，调高德前转 GCJ-02 | 不转地址偏 ~500 米（国内地图经典坑，`lib/geo.js` 30 行解决） |
| 高德 key 只在服务端 | skill 开源分发也不泄 key |
| nearby/geocode 限流 10 次/分/IP | 防爬取 + 防刷高德免费配额（实测免费 key QPS 也就在这个量级） |

## 已知问题（诚实清单）

1. **裸 HTTP**：secret、位置、联系方式明文传输。上 HTTPS 需要域名（国内服务器还需 ICP 备案）
2. **nearby 无鉴权**：任何知道地址的人都能在限流内慢慢爬走公开资料。限流只是减速带，不是门
3. **伪造位置无防范**：上报假坐标畅通无阻（微信附近的人同样如此，产品属性）
4. **内容零审核**：昵称/简介/联系方式无敏感词、无举报通道
5. **secret 丢失 = 死锁**：删资料必须凭 secret，丢了只能服务器管理员手动清（运维手册有命令）
6. **GPS 定位仅 Windows**：macOS/Linux 落到 IP 城市级或手填
7. **IP 名额的边界**：动态 IP 用户理论上可多次创建；NAT 多设备会被误拦
8. **单点无备份无告警**：一台轻量服务器，pm2 挂了没人知道，data.db 丢了就丢了

## 从概念到「全国可用」需要什么

| 项 | 现状 | 全国化需要 | 量级估算 |
|---|---|---|---|
| 域名 + HTTPS | 裸 IP:3210 | 域名 + Caddy/Let's Encrypt | 域名 ~60 元/年 |
| 合规 | 无 | **ICP 备案**（国内服务器硬要求）+ 隐私政策 + 用户协议 | 个人备案 2~4 周，免费 |
| 身份体系 | IP + UUID | 注册制或邀请码（接入 GitHub/微信 OAuth），根治灌水与爬取 | 开发 1~2 周 |
| 内容安全 | 无 | 敏感词过滤 + 内容安全 API（如腾讯天御）+ 举报处置 | 按量计费，万级用户约几十元/月 |
| 个人信息保护 | 删除接口 | 最小化收集 + 默认模糊到区县 + 点对点授权看联系方式 | 产品改造 |
| 高德配额 | 个人免费 5000 次/天 | 企业认证或付费档 | 百元级/月起 |
| 服务器 | 2C4G 轻量 | 万人级：负载均衡 + Redis 限流 + 每日备份 + 监控告警 | 100~500 元/月 |
| 防爬纵深 | 内存限流 | 注册制 + 数据脱敏展示 + 行为风控 | 随账号体系一起做 |

一句话：**概念版到「朋友圈可用」已经到了；到「全国可用」，贵的主要不是服务器，是合规和身份体系。**

## 欢迎改造

这个仓库就是给你fork的。一些现成的方向：

- macOS/Linux 的 GPS 定位（`scripts/get_location.ps1` 的等价物）
- 把 nearby 结果渲染成地图（网页端、甚至 MCP 工具）
- 注册制/邀请码替换 IP 防灌水
- 联系方式点对点授权可见（而非全公开）
- HTTPS + Caddy 一键部署脚本
- 服务端从 SQLite 到 PostgreSQL（用户量上来后）
